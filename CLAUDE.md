# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static marketing site for **MET Clinic** (Dra. Melina Trujillo — gynecological aesthetics & antiaging). No build step, no framework: plain HTML + CSS + vanilla JS served directly by GitHub Pages.

## Deployment

GitHub Pages serves from the `gh-pages` branch (not `main`). Deploy is a force push, no CI:

```bash
git push origin main:gh-pages --force
```

Live URL: https://sebastiancordoba.github.io/met-clinic/ (temporary; the final domain, https://metclinic.com.mx, is not connected yet; see «SEO and sharing»)

There is no build, lint, or test pipeline. To preview locally, just open `index.html` in a browser (or `python3 -m http.server` from the repo root if `file://` blocks fonts/images).

## PDF generation (one-off tool)

`generate-pdf.mjs` is a Puppeteer script that screenshots each `.proposal .mockup` block in `propuestas.html` and assembles them into `propuestas_paletas_colores.pdf`. It is not part of the site — it's a brand-deliverable generator.

```bash
npm install            # installs puppeteer
node generate-pdf.mjs
```

## File map (what each top-level file is for)

- `index.html` — the live site. **All CSS lives inline in `<style>`.** ~1000 lines of HTML + ~1500 lines of CSS in one file is intentional; do not split it unless asked.
- `main.js` — runtime behavior for `index.html` only (nav, carousel, scroll-reveal, counters, hamburger). Loaded as a plain `<script>`, no modules.
- `style.css` + `script.js` — **legacy v1 assets**, no longer referenced by `index.html`. Don't edit them unless explicitly asked; the live site uses inline styles + `main.js`.
- `brand-explorer.html`, `propuestas.html`, `propuestas-print.html` — internal design artifacts (brand exploration, palette/typography proposals). Self-contained pages; not linked from `index.html`.
- `images/web/` — **what the site actually serves**: resized WebP derived from the originals in `BRANDING/` and the repo root. Generated by `optimizar-imagenes.py`; never edit by hand.
- `BRANDING/webfonts/` — the brand fonts as WOFF2, generated by `optimizar-fuentes.py`. The HTML and `pilares.css` load these, not the OTFs.
- `clinic.png`, `foto_jardin.png` — **originals**, not referenced by the site. They stay here as the source for regenerating the derivatives.
- `images/servicios/` — the six service-card photos (`01-…` through `06-…`), referenced by `index.html`.
- `BRANDING/` — source brand assets (fonts, palettes, logos). Fonts here are loaded via `@font-face` in the HTML files using their on-disk paths — **the `BRANDING/` directory ships with the site**, so don't rename or move files inside it without updating every `@font-face` and `<img>` src that points to them.
- `Dra Melina Trujillo.pdf` — source of truth for medical bio, credentials, associations, and service names. When the user says "use what's in the PDF," this is the file.

Things worth knowing before editing:

- **Nav offset is 68px.** Fixed nav height is hardcoded; smooth-scroll in `main.js` subtracts 68, and several sections size themselves to `calc(100dvh - 68px)`. If you change nav height, hunt down all three.
- **`.is-dark` sections** flip the nav to a dark theme on scroll (`main.js` toggles `nav.dark-section`). No section uses it today — the site stays on the light palette — but the mechanism is still there.
- **Que cada bloque quepa en la pantalla (24-oct, Sebas).** Cada bloque que no se debe partir (tarjeta, foto, mapa
  con su tarjeta, la columna de título de un grupo de tratamientos) cabe entero en el alto útil: pantalla − 68 px de
  la barra (− 67 de la barra fija en el teléfono), en 1280×680, 1440×900, 1920×1080, iPad e iPhone. Las fotos se topan
  con `100svh` y enfocan la cara. En las páginas de servicio la columna izquierda de cada grupo es `sticky`; por eso
  `html`/`body` usan `overflow-x:clip` y no `hidden` (hidden rompe sticky). Las anclas ya bajan bajo la barra con
  `scroll-padding-top`. Sin scroll-snap: con listas largas brincaba.
- **One-screen layout pattern.** `#sobre-block` and `#servicios` are constrained to `height: calc(100dvh - 68px)` and use flex column children with `flex:1 / min-height:0` so content fills exactly one viewport. Be careful with padding/margins inside them — small additions overflow and clip.
- **Bordes redondeados (default since 24-oct-2026, Sebas chose them).** One radius scale: `--r-sm` 8, `--r-md` 14,
  `--r-lg` 20, `--r-pill` 999 (buttons, chips). The block lives under `html.redondeado` at the end of `index.html`'s
  `<style>` **and** of `pilares.css`, so a change goes in both. Every page's `<html>` carries the class;
  `?estilo=actual` removes it to compare with the old square corners (URL only: no visible switch and nothing is remembered; Sebas asked to remove the floating switch on 24-oct). The mockup (`met-clinic-maqueta/maqueta.css`)
  uses the same scale.
- **Brand tokens** live in `:root` (`--sage`, `--tranquil`, `--confort`, `--dark`, `--texto-suave`, `--font`, `--ease`). Use these instead of hex values.
- **Color rules (brandbook p. 17-18, applied Oct 2026):**
  - Small text never goes in `--sage`: on cream it's 3.2:1 and small text needs 4.5:1. Use `--texto-suave` (#515151, the official "Formalidad 80%" tint, 6.8:1). Sage is for large headings, the Larken accents, lines and icons.
  - Section backgrounds alternate **only** `--tranquil` and `--confort` — no plain white sections. Exception: `#tecnologia` (the equipment gallery closing #servicios) is a full-width band in warm stone `#ECE8E2` (Sebas chose it on 25-nov). `#filosofia` is the one block on `--sage`; only large text goes there (its stats sit on cream cards). The one small label, its eyebrow, uses `#111` (5.1:1) because `--dark` only reaches 4.08:1 on sage.
  - Translucent dark text stays at alpha ≥ 0.75.
  - Check with axe-core before shipping color changes.

### Services carousel (`#svcCarousel` + IIFE in `main.js`)

The trickiest piece. There are 6 real cards; the IIFE clones 2 in front and 3 behind for seamless looping, then auto-advances every 4s with a snap-back when it reaches the clone of card 0.

- **Desktop:** active card is 10/12 of the container width, with 1/12 peek on each side. Centering uses `translateX(-cur * w + (C - w) / 2)` where `C = container width`, `w = card width`. Edge fades (`::before` / `::after`) are desktop-only (`min-width: 641px`).
- **Mobile (≤640px):** one card at full width, no peek, no fades. The `isDesktop()` check in `cw()` and `render()` switches modes; both must stay in sync.
- Card states: `s-active` (centered), `s-side` (peeking, desktop only), `s-hidden` (everything else). CSS dims/sides accordingly.

## Page weight

The files in `BRANDING/` are print resolution: `MET_POSITIVO_04.png` is 11117x4501 px and the nav renders it 40 px tall. Served as-is, a first visit cost **7.9 MB**; with the `images/web/` derivatives and the WOFF2 fonts it's **~960 KB**.

Two scripts, both reproducible, each carrying its own size table:

```bash
python3 optimizar-imagenes.py   # BRANDING/ + root → images/web/*.webp
python3 optimizar-fuentes.py    # OTF → BRANDING/webfonts/*.woff2
```

To replace a logo or a photo, swap the **original** and re-run the script. Never edit a derivative — the next run overwrites it.

The `.webp` files ship without a PNG fallback on purpose: every browser has supported it for years, and a `<picture>` element per logo doesn't pay for itself.

## SEO and sharing

Every page carries canonical, favicon, Open Graph and Twitter card tags; `index.html` also carries `MedicalClinic` JSON-LD. `sitemap.xml` and `robots.txt` live at the root — robots excludes the internal design artifacts.

**The absolute URLs are hardcoded** and, since 24-oct-2026, point at the final domain `https://metclinic.com.mx` (canonical, `og:url`, `og:image`, JSON-LD, sitemap, robots). `metclinic.mx` also belongs to the clinic and only 301-redirects to `.com.mx`; never use it in the markup. Both domains are bought but **not connected**: Sebas connects DNS, Pages and Search Console only when he approves the site as finished. Until then the canonicals point at a domain that doesn't serve anything yet, so don't push this branch to `gh-pages`. Launch steps: `~/hermes-workspace/reportes/2026-10-24-lanzamiento-dominio.md`. The `CNAME` file for Pages is created on launch day, not before.

Deliberately **not** in the structured data: `aggregateRating` and `openingHours`. Google penalises review markup that doesn't match real data — the reviews live on Doctoralia, not here — and nobody has told us the opening hours. Add hours when someone confirms them.

The Open Graph image (`images/web/og-metclinic.jpg`, 1200x630) is generated by `optimizar-imagenes.py`. It's what shows when the link is pasted into WhatsApp, which is how a doctor gets recommended in Mexico.

## Conventions

- **Spanish UI copy.** Site is in es-MX. Match tone (formal "usted" is avoided; warm clinical voice).
- **Inline styles in `index.html`.** Don't extract to a separate stylesheet — the current setup is deliberate for GitHub Pages simplicity.
- **No frameworks, no bundler, no npm runtime deps.** `package.json` only carries `puppeteer` for the PDF script. Don't add React/Vue/Tailwind/etc.
- **File paths with spaces:** the repo lives under iCloud (`~/Library/Mobile Documents/com~apple~CloudDocs/...`). Always quote paths in shell commands. Note also that the `BRANDING/DRA. MT/` directory has a space and a period in its name and is referenced from `@font-face` URLs — leave it alone.
- **PDF + heavy assets** are gitignored (`.gitignore` excludes `*.pdf`), but `Dra Melina Trujillo.pdf` and `propuestas_paletas_colores.pdf` are tracked historically; check `git status` before committing large binaries.
